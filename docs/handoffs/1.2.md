## HANDOFF FOR CLAUDE SONNET: Scales Build chat, 1.2 item 1, box breathing

**Steps that can't be undone first:**
- **Never merge, and never open a PR to `main`.** A merge to `main` touching `ios/` uploads a TestFlight build
  (`ios.yml`). PRs go to `next-1.2`; Claude merges them there on Graham's merge go.
- **Never push to `main`, `ios`, `release` or `testflight`. Never run `listing.yml`.** You may run `ios.yml` by hand
  (workflow_dispatch) on your own feature branch only: there it compiles and stops, because signing and upload run
  only on `main`. Never dispatch it on `main`.

**Read first:** grahamdeno/playbook `rules.md` and `standards/design.md`; `HANDOFF.md` (Design rules, Where things
live); `docs/roadmap.md` item 1 (the acceptance criteria).

**Branch:** `breathe-box`, from `next-1.2`, PR into `next-1.2`.

**Touch:** `index.html` (the Breathing words row, `breatheLater`/`breatheOff`, the breathe CSS), `core.js`
(`recordVisit` gets an optional `breath` flag stored on the visit as `breath: 1`), `scripts/evaluate.js` (report
breathing visits apart), `ios/App/Haptics.swift`, `ios/App/WebViewController.swift` (only if a stop message needs a
new case), tests.

**Don't touch:** the timing lines (20 s / 30 s), the pile rules, Scales Full, stored keys other than `ui.breathe`.

**Build notes:**
- `ui.breathe` becomes `"off" | "gentle" | "box"`. Read old values safely: `false` is off; `true` or missing is
  gentle. Never rewrite other `ui` fields.
- The Settings row follows the existing Look pattern: three words, the chosen one marked, `aria-checked` or
  `aria-pressed` as that pattern does, 44 pt targets.
- Box breathing: one constant `BOX_SCALE = 0.018`, 4 s per phase, ease in and out, `transform-origin: left center`.
  Drive phases from one timer in the page so words and haptics stay in step.
- Haptics: two new native styles. `breathIn` plays a 4 s continuous Core Haptics event, intensity rising 0.15 to 0.6,
  sharpness 0.15. `breathOut` falls 0.6 to 0.15 over 4 s. `breathStop` stops any breath pattern at once (keep a
  reference to the player). No Core Haptics: play nothing.
- Stop on any touch, mode change, `visibilitychange` hidden, or leaving the reading screen; send `breathStop`.
- Reduce Motion: no scale, haptics still sent.
- The visit records `breath: 1` only if at least one full in-breath played during it.

**Done when:** a test per acceptance criterion (unit tests for the setting migration and the visit flag; a browser
test for start after 20 s, stop on touch, Reduce Motion); `node --test` and `node tests/e2e/app.e2e.js` pass; the
version bumped to 2.38.0 everywhere HANDOFF.md lists; PR open with status "Waiting for review" in the playbook PR
format, Triggers line "Into next-1.2: uploads and deploys nothing". `ios.yml` run by hand on the branch passes its
compile step.

**Always review:** yes (stored data, a new native message).

**If anything isn't Ready:** stop and say what's missing.

- Put every number in one place at the top of the pattern so tuning is a one-line change.

## HANDOFF FOR CLAUDE SONNET: Scales Build chat, 1.2 item 3, Share Sheet import

**Steps that can't be undone first:**
- **Never merge** (touches `ios/`; a merge uploads). **Never push to `main`, `ios`, `release` or `testflight`.** `ios.yml` by
  hand on your feature branch only (compiles, never uploads there).
- **Don't create identifiers.** Grok registers `group.com.grahamdeno.scales` and `com.grahamdeno.scales.share` in the
  Apple Developer portal. Use exactly those strings.

**Read first:** `docs/roadmap.md` item 3; `ios/project.yml`; `ios/App/NativeStore.swift`; `.github/workflows/ios.yml`
(signing: the archive is unsigned, then ad hoc signed with entitlements before export).

**Branch:** `share-import`, from `next-1.2` after item 2 merges there, PR into `next-1.2`.

**Touch:** `ios/project.yml` (a new `ScalesShare` app-extension target, bundle ID `com.grahamdeno.scales.share`,
embedded in Scales), `ios/Share/` (new: the extension's view controller, Info.plist, entitlements, privacy manifest),
`ios/App/Scales.entitlements` (add the App Group), `ios/App/WebViewController.swift` (deliver the inbox to the page),
`.github/workflows/ios.yml` (ad hoc sign the extension with its own entitlements before the app; check both in the
signed export), `index.html` (receive inbox items), tests.

**Don't touch:** the iCloud container, NativeStore's saved data format, App Privacy answers.

**Build notes:**
- Extension accepts plain text and URLs (`NSExtensionActivationSupportsText`, `...WebURLWithMaxCount: 1`).
- Sheet in Scales' plum and bone: editable text, a Source line, Keep and Cancel as words, 44 pt targets, Dynamic Type.
  Keep is disabled while the text is empty. Text limit matches Write's.
- Keep appends `{id, text, source, at}` to `inbox.json` in the App Group container (atomic write), then closes.
- On launch and on return to the foreground, the app reads the inbox and posts `{type: "inbox", items}` to the page.
  The page adds each as a new thought through the same path Write uses, skipping any `id` already added, then posts
  `{type: "inboxDone", ids}`. Only then does the app remove those entries. A crash between the two adds nothing twice
  and loses nothing.
- Nothing is sent off the phone; the privacy guard and privacy manifests stay as they are (the extension gets its own
  manifest: no tracking, no collected data).

**Done when:** unit tests for the page side (add, skip duplicate ids, done message); `ios.yml` run by hand on the branch compiles
both targets; the signed-export check for the App Group entitlement in the app and the extension is written (it first runs on the
test build); PR
open, "Waiting for review", Triggers line as item 1. Note in Limitations that the first signed build needs Grok's
identifiers in place.

**Always review:** yes (entitlements, a new target, the release workflow, stored data).

**Report back:** PR link, tests table. **Next step:** Opus reviews.
